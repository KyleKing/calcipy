Adopt vale-ai-tells for Prose Linting (Beta)⚓︎

  • Status: proposed
  • Date: 2026-08-01
  • Deciders: KyleKing
  • Consulted: AI slop detection research
  • Informed: calcipy users and contributors

Context and Problem Statement⚓︎

A growing share of prose in this and other repositories starts as an AI draft. Word-list filters (“delve”, “tapestry”, em dashes) go stale every time a new model release brings a new set of tells, so a fixed ban list is a losing game.

“AI slop detection” actually covers two separate questions:

  • Provenance: was this text generated by a model
  • Quality: does this read like machine boilerplate, regardless of who typed it

For a solo maintainer editing AI drafts by hand, provenance is the wrong question. A detector that flags an edited-from-a-draft paragraph the same as unedited slop provides no actionable signal. Quality is what’s useful, and it is what a prose linter can check offline, deterministically, in a pre-commit hook.

How should calcipy support AI-slop-style prose linting, given the tool needs to run offline, catch the class of tell rather than a fixed vocabulary, and fit a project that already writes changelog entries, migration notes, and ADRs by hand?

Decision Drivers⚓︎

  • Must run fully offline, no API calls, no GPU
  • Must be fast enough for a pre-commit hook, not a batch job
  • Must degrade gracefully as models change, rather than needing constant re-tuning
  • Should catch structural tells (list-heavy prose, “not just X, but Y” framing), not only lexical ones, since lexical bans go stale fastest
  • Should stay optional (beta): false positives on domain vocabulary and existing docs conventions are expected and must not block unrelated commits
  • Small project, solo maintainer: adoption cost must stay low

Considered Options⚓︎

  • vale-ai-tells (offline prose linter, 77 rules, structural and lexical)
  • slop-forensics (corpus profiler, builds a word list from your own writing)
  • Binoculars / Fast-DetectGPT (perplexity-based provenance detectors)
  • Pangram (commercial provenance classifier, API-based)
  • No tooling, continue relying on manual review and CLAUDE.md style rules

Decision Outcome⚓︎

Chosen option: “vale-ai-tells”, wired into calcipy as a beta lint.prose task (calcipy-lint lint.prose), because it answers the quality question directly, runs offline, and drops into the existing prek/pre-commit pipeline the same way lint.fix and tags already do.

The task requires vale installed separately (same pattern as pyright), runs vale sync to pull the ai-tells style package, then lints the target path. It ships at the manual pre-commit stage rather than pre-commit or pre-push, so it never blocks a commit until the false-positive rate has been tuned per repo.

Perplexity detectors and commercial classifiers answer provenance, which is not the question this project needs answered: I already know which paragraphs started as an AI draft. They also require a resident model (two 7B models for Binoculars) or a network call, neither of which fits an offline pre-commit hook.

slop-forensics is not adopted as a hook, but the ADR-research writeup keeps it as a documented option: it builds a corpus-specific word list from your own output, which is the only mechanism found that survives a model version change. It is a candidate for an occasional batch job, not a per-commit check.

A second, separate beta task ships alongside lint.prose: lint.slop-export writes the Markdown-to-JSONL adapter slop-forensics needs (front matter, fences, links, and headings stripped, documents under 150 words dropped). The adapter is first-party Python with no heavy dependencies, so it lives in calcipy directly. Running the profiler itself still requires a separate slop-forensics checkout with its own nltk/wordfreq venv, which lint.slop-export does not attempt to install or wrap; it prints the follow-up command instead.

Consequences⚓︎

  • Good, because the check is deterministic and reproducible, no model inference
  • Good, because it degrades gracefully: structural rules (VerbTricolon, CataphoricForecasting, MicDrop) don’t depend on a specific model’s vocabulary
  • Good, because it reuses the existing prek/pre-commit and calcipy-lint plumbing
  • Good, because the manual stage keeps it opt-in until tuned, consistent with “beta”
  • Bad, because it requires a separate binary install (vale), same class of dependency as pyright
  • Bad, because vale sync fetches the style package over the network, so the task cannot run fully airgapped without a pre-populated StylesPath
  • Bad, because false positives are expected on domain vocabulary (figurative-verb rules fire on literal game terms like “dial lands on”) and on existing docs conventions (ColonUsage fires on every **Label:** Sentence bullet); both need a per-repo disable list
  • Neutral, because this sits in tension with calcipy’s broader move toward a thinner library (see the tooling-refactor notes moving wrapper tasks to template-distributed config); if that migration proceeds, lint.prose is a candidate to move to a template-distributed hook rather than staying in calcipy itself

Pros and Cons of the Options⚓︎

vale-ai-tells⚓︎

  • Good, because it runs offline and matches pre-commit’s exit-code contract
  • Good, because most rules are structural, not lexical, so they outlive a given model
  • Good, because Vale is already a known quantity for prose linting
  • Bad, because it needs a per-repo disable list to avoid drowning in domain-vocabulary false positives
  • Neutral, because “read like machine boilerplate” is fuzzy at the edges; some rules will always need judgment calls

slop-forensics⚓︎

  • Good, because it adapts to the author’s own corpus instead of a fixed word list
  • Good, because the slop_score output agreed with vale-ai-tells’ ranking (calcipy scored 8x lower than a more casually-drafted comparison repo, by two independent methods)
  • Bad, because it targets JSONL of model generations, so Markdown needs an adapter script (front matter, fences, and links stripped before scoring)
  • Bad, because the word-list output is dominated by domain vocabulary against a general English baseline (madr, pypi, rulebook) unless profiled against a matched corpus
  • Bad, because it’s a batch analysis step, not something that fits a fast pre-commit hook

Binoculars / Fast-DetectGPT⚓︎

  • Good, because published detection rates are high (>90% at 0.01% false positives for Binoculars) against 2023-era generations
  • Bad, because they answer provenance, not quality, which isn’t the question this project needs answered
  • Bad, because they degrade against newer models, heavy editing, and prompted style
  • Bad, because Binoculars needs two resident 7B models; neither fits an offline, lightweight hook

Pangram⚓︎

  • Good, because it reports the lowest published false-positive rate among commercial classifiers
  • Bad, because it’s an API call, which breaks the offline requirement
  • Bad, because it answers provenance, same objection as the perplexity detectors

No tooling⚓︎

  • Good, because zero maintenance cost
  • Bad, because manual review misses tells consistently, and CLAUDE.md’s style rules have no automated enforcement

Validation⚓︎

We will validate this decision by:

  • Running lint.prose at the manual stage on calcipy’s own docs for at least one release cycle before considering the pre-commit or pre-push stage
  • Tracking whether the per-repo disable list (ColonUsage off in .vale.ini) stays small; a growing disable list signals the style pack doesn’t fit this project’s docs conventions
  • Judging lint.slop-export against a real corpus before it leaves beta. calcipy’s own docs export to 33 documents and 33,182 words, which is thin for the n-gram fingerprinting slop-forensics does, so the open question is whether a repo this size yields a stable word list at all

We will revisit this decision if:

  • The false-positive rate stays high enough that the check gets ignored rather than acted on
  • calcipy’s scope-reduction effort (moving wrapper tasks to template-distributed tooling) reaches linting tasks, in which case lint.prose moves to the template instead of shipping inside calcipy
  • A model-agnostic provenance question becomes the actual need, which would reopen the perplexity/classifier options
  • lint.prose stays unusable in template children. vale exits with a runtime error when no .vale.ini is present and calcipy ships none, so the task only runs in repos that hand-wrote the config. Closing that means either passing --config with a packaged default or distributing the file from calcipy_template

Appendix: Tool Catalog⚓︎

Full landscape survey, checked as of 2026-08-01. Checked says how far the research went: ran means installed and used, read means the project’s own docs were read, cited means the claim rests on a search-result summary or third-party source.

Prose linters⚓︎

Answer “does this read like machine boilerplate”. Deterministic, offline, and hook-friendly.

Tool Checked Description
vale-ai-tells ran Vale package, 77 rules. Goes past word lists into participial padding, contrastive negation, count-forecasting lead-ins, verb tricolons, and anthropomorphic clichés. Separate opt-in style for commit messages.
slop-gate read Zero-dependency npm CLI. ~40 English tells plus translationese packs for Korean, Russian, Vietnamese, Chinese, and Filipino. Exits 1 for CI, and --baseline grandfathers existing tells.
Signs of AI Writing read Vale ruleset built from Wikipedia’s field guide of patterns editors actually flagged on real articles.
Vale ran The prose linter itself. Everything above is a package for it.
proselint cited General style-guide linter. Predates the AI question, still catches overlapping tics.
write-good cited Flags weak, passive, and wordy phrasing.
alex cited Insensitive-language linter. Adjacent rather than slop-focused.
LanguageTool cited Open-source multilingual grammar and style checker.

Corpus profilers⚓︎

Build the word list instead of bundling one, the only escape from list staleness.

Tool Checked Description
slop-forensics ran Computes over-represented words and n-grams against a human baseline to produce a per-corpus fingerprint, plus a scalar slop_score (weighted hits per 1000 tokens). Also clusters models phylogenetically by lexical habit. Needs a JSONL adapter for arbitrary text, which is what lint.slop-export provides.
EQ-Bench Slop Score cited Public leaderboard scoring frontier models on slop. Same author as slop-forensics.
Antislop framework cited ICLR 2026 paper on identifying and suppressing slop patterns. Reports overuse ratios up to 85,000x human frequency.

Zero-shot detectors⚓︎

Answer “was this generated by a model”, a different question and mostly not the one this project needs answered. Both degrade against post-2023 models and heavy editing.

Tool Checked Description
Binoculars read ICML 2024. Ratio of a text’s log-perplexity under an observer model to the cross-perplexity between observer and performer, which cancels the prompt-difficulty confound. Claims >90% detection at 0.01% false positives. Wants two 7B models resident.
Fast-DetectGPT read ICLR 2024. Conditional probability curvature, replacing DetectGPT’s perturbation step with sampling. Claims ~75% relative improvement over DetectGPT at 340x the speed, and works black-box.

Commercial classifiers⚓︎

API-only, no official CLI, though each is a single POST.

Tool Checked Description
Pangram cited Claims ~0.004% false positives. Chicago Booth found it the only detector meeting a 0.5% policy cap without losing detection power, and a 2026 VUB paper reached a similar conclusion.
GPTZero cited Education-focused. Claims 1% false positives, where Pangram’s benchmark measured 2.01%. GPTZero’s own comparison reverses the ranking. Read both as marketing.
Originality.ai cited AI detection bundled with plagiarism checking.

Code slop linters⚓︎

Different target: what coding agents leave behind in source, rather than prose.

Tool Checked Description
AI-SLOP-Detector cited 50+ rules across 8 languages. Targets code that looks finished and is not, from empty function bodies to imports of packages that do not exist to docs that oversell what the code does. Also on PyPI.
antislop cited Multi-language linter for lazily generated code, deferrals, hedging, and placeholders.
grain cited Configurable rules for obvious comments, naked excepts, hedge words, and vague TODOs, including markdown hedge detection.

Agent-side editing skills⚓︎

Rewrite rather than report, so they belong in the drafting loop rather than a hook. Worth reading for their pattern catalogs even if never installed.

Tool Checked Description
no-ai-slop cited MIT skill for Claude Code, Codex, and others. Edits out 20+ patterns, and has an audit mode that quotes each hit without rewriting.
stop-slop cited Cuts filler, throat-clearing openers, emphasis crutches, and adverbs.
anti-ai-slop-writing cited Same idea, targeting 8+ agent harnesses.
antislop-sampler cited Suppresses known phrases at generation time rather than editing after.
im-not-ai cited Claude Code skill removing Korean translationese.

Picking one⚓︎

vale-ai-tells does the most work per unit of setup for prose in this repo, and its rules line up with the existing voice rules in CLAUDE.md. slop-gate is the faster answer for npx and nothing else. slop-forensics is the batch job that keeps the word list from going stale, which is why it backs the second beta task (lint.slop-export) rather than the pre-commit hook. Everything under zero-shot detectors and commercial classifiers answers a question this project does not have.
