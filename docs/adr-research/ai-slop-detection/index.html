Detecting AI slop in prose⚓︎

Research backing ADR-0008: Adopt vale-ai-tells for Prose Linting.

The problem⚓︎

Word lists go stale. Ban “delve”, then “tapestry”, then em dashes, and the next model release brings a new set. What I want is tooling that catches the class of tell, runs offline, and fits in a pre-commit hook.

The phrase “AI slop detection” covers separate questions, and the tooling splits along that line:

  • Provenance (was this generated by a model) is what classifiers and perplexity methods answer
  • Quality (does this read like machine boilerplate) is what prose linters answer

For my own writing the second question is the useful one. Provenance detectors will flag an edited-from-an-AI-draft paragraph the same as pure slop, which tells me nothing I want to act on.

Landscape⚓︎

Tool Kind Runs Notes
vale-ai-tells Prose linter Offline 77 rules, structural not just lexical
slop-gate Prose linter Offline npx, ~40 tells, --baseline mode
Signs of AI Writing Vale ruleset Offline Derived from Wikipedia’s field guide
slop-forensics Corpus profiler Offline Builds word lists from your own corpus
Binoculars Perplexity detector 2x 7B models ICML 2024, needs a GPU
Fast-DetectGPT Perplexity detector 1 local model ICLR 2024, 340x faster than DetectGPT
Pangram Commercial classifier API Lowest published false-positive rate

awesome-slop catalogs the rest, including per-language word lists.

Why the perplexity methods are a dead end for me⚓︎

Binoculars scores the ratio of a text’s log-perplexity under an observer model against the cross-perplexity between an observer and a performer model. That normalization cancels the prompt-difficulty confound that makes raw perplexity useless on technical writing, which is a clever fix. Reported numbers are

90% detection at 0.01% false positives.

Both it and Fast-DetectGPT were tuned on 2023-era generations and degrade against newer models, heavy editing, and prompted style. They also answer the provenance question. Two 7B models resident to learn that a doc I already know I drafted with Claude was drafted with Claude is not a trade I want.

Building the word list from your own corpus⚓︎

slop-forensics is the interesting one. Instead of a fixed word list it computes over-representation of words and n-grams against a human baseline, producing a “slop fingerprint” per corpus. Point it at my own output and it generates a word list specific to whatever model I actually use, which is the only way out of the staleness problem.

Exit code is 1 when alerts fire, so it drops into hk or CI unchanged.

The rules worth having go past vocabulary. CataphoricForecasting catches “Three markers:” announcing a count before the items. ContrastiveNegation catches “no letter counts, no positions, no rhymes”. AnthropomorphicJustification catches “load-bearing”. VerbTricolon catches three-verb enumerations clustered in one paragraph. MicDrop catches the isolated two-word closer. LabelAndExplain catches “The problem:” as a bullet lead-in.

Demo 2: slop-forensics⚓︎

slop_profile.py reads JSONL of model generations, so an arbitrary corpus of Markdown needs an adapter. Records need model, source, id, and output, in a file named generated_<name>.jsonl.

Watch for two things during install. requirements.txt pulls ete3 and PyQt5, which are needed only for the phylogeny charts, so skip them. NLTK’s import hardening blocks any module that resolves inside the current working directory, which means the venv must live outside the directory you run from, and anything under /tmp fails because /tmp resolves through /private/tmp.

FENCE = re.compile(r'^```.*?^```', re.MULTILINE | re.DOTALL)
FRONTMATTER = re.compile(r'\A---\n.*?\n---\n', re.DOTALL)
INLINE_CODE = re.compile(r'`[^`]+`')
LINK = re.compile(r'\[([^\]]*)\]\([^)]*\)')
HEADING_MARK = re.compile(r'^#{1,6}\s+', re.MULTILINE)


def to_prose(raw: str) -> str:
    text = FRONTMATTER.sub('', raw)
    text = FENCE.sub('', text)
    text = INLINE_CODE.sub('', text)
    text = LINK.sub(r'\1', text)
    return HEADING_MARK.sub('', text).strip()


record = {'model': name, 'source': 'repo', 'id': rel_path, 'output': to_prose(body)}

slop_score is weighted hits per 1000 tokens against the bundled lists of 1000 words, 200 bigrams, and 200 trigrams, with bigrams counted double and trigrams counted 8x.

Results⚓︎

Run against calcipy (26 prose files, 30,369 words) and boardgame-teaches (18 files, 16,676 words).

Metric calcipy boardgame-teaches
Vale alerts per 1k words 23.4 20.1
Same, excluding ColonUsage 6.7 18.7
slop-forensics slop_score 0.13 1.08
repetition_score 16.4 26.9

The raw Vale counts say the two repos are about equal. They are not. 510 of calcipy’s 712 alerts are ColonUsage, a capitalization rule that fires on every **Label:** Sentence bullet, which is a docs convention rather than a tell. Drop that one rule and calcipy sits at a third of boardgame-teaches. slop_score agrees at 8x, computed by a completely independent method, which is the part that makes me trust the ranking.

That fits how the two were written. calcipy’s prose is mostly changelog, migration notes, and ADRs. boardgame-teaches is drafted long-form and the tells cluster in exports/.

Per-repo top rules, excluding ColonUsage:

  • calcipy leans lexical, with FormalRegister (72) and OverusedVocabulary (55) carrying most of it, concentrated in docs/docs/adr-research/
  • boardgame-teaches leans structural, with EmDashUsage (140), VerbTricolon (44), CataphoricForecasting (16), and LabelAndExplain (15)

The adr-research/ files in calcipy are the worst offenders (89, 76, and 72 alerts), which is unsurprising for research summaries. docs/docs/STYLE_GUIDE.md:133 says “Comprehensive Guide” and :81 opens with “ready to get started”.

slop-forensics’ over-represented word lists were the least useful output. Measured against a general English baseline, calcipy’s top words are madr, linting, adrs, pypi, and the MIT license boilerplate, while boardgame-teaches returns encryptor, pamir, rulebook, and rupees. That is domain vocabulary, not slop. The scalar slop_score is the signal. The word lists only become interesting when you profile several corpora written the same way and diff them.

False positives to expect⚓︎

Game vocabulary trips the figurative-verb rules. “Dial lands on” in Wavelength and “Trophy wins.” in Looot are literal, and the rule docs say as much (“disable this rule for athletics”). ShipOveruse fires on the software sense of ship. Any adopted config needs a per-repo disable list.

This file trips its own linter seven times, all of them quoted examples of tells. Vale skips inline code, so wrap quoted examples in backticks if you want a doc about slop to come back clean.

What I’d adopt⚓︎

Wire vale-ai-tells into hk as a prose step with ColonUsage off, EmDashUsage on (it matches my own rule), and the figurative-verb rules off in boardgame-teaches/exports/. It is deterministic, offline, and fast enough for a pre-commit hook, and it encodes most of my voice rules mechanically.

Keep slop-forensics as an occasional batch job rather than a hook. Regenerating a custom Vale vocabulary from recent output every few months solves the staleness problem that kills every static rule pack.

Skip the perplexity detectors and the commercial classifiers. They answer the provenance question, and I already know the answer.

calcipy now ships both as beta tasks: lint.prose wraps vale-ai-tells for the pre-commit step, and lint.slop-export writes the JSONL adapter slop-forensics needs for the batch job. The full tool landscape, including the tools not adopted, moved to ADR-0008’s appendix.
